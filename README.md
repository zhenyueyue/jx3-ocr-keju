# 剑网3 科举助手

一个面向 Windows 的剑网3科举答题辅助工具。

打开科举界面后，只需要框选一次 **题目 + 全部答案选项** 的区域，程序就会持续检测换题、自动识别题目，并直接在游戏画面上框出正确答案。

不需要每道题按快捷键，也不需要上传游戏截图。

---

## 主要功能

- 实时检测科举题目变化
- 本地 OCR 自动识别题干和选项
- 自动匹配本地科举题库
- 本地没有时自动查询 JX3BOX
- 正确答案直接在游戏画面原位置描边
- 未收录题目可以边用边补
- 用户补录答案优先于远端题库
- 自动记住上一次框选区域
- 题库和设置独立保存，更新程序不会丢失
- 支持暂停实时检测和手动立即检测

---

## 下载与运行

前往 [GitHub Releases](https://github.com/zhenyueyue/jx3-ocr-keju/releases) 下载 Windows x64 压缩包。

下载后请 **完整解压整个压缩包**，不要只单独复制其中的 `ocr-keju.exe`。

正常目录类似：

```text
ocr-keju/
├─ ocr-keju.exe
└─ _internal/
```

运行 `ocr-keju.exe` 即可。

> `build/` 是开发构建时的临时目录，不是给用户运行的版本。正常使用只需要 Release 压缩包或 `dist/ocr-keju/` 中的完整程序。

---

## 第一次使用

1. 打开程序。
2. 点击 **同步题库**，下载当前可用的科举题库。
3. 在剑网3中打开科举答题界面。
4. 点击 **重新框选识别区域**。
5. 把完整的 **题目 + 所有答案选项** 一起框进去。
6. 框选完成后，实时检测会自动开启。

推荐框选范围：

```text
┌──────────────────────────────┐
│ 题目：XXXXXXXXXXXX？          │
│                              │
│ A. XXXXX                     │
│ B. XXXXX                     │
│ C. XXXXX                     │
│ D. XXXXX                     │
└──────────────────────────────┘
```

尽量不要把聊天框、倒计时动画、NPC、背景特效等无关内容一起框进去。**框选越紧凑，识别速度通常越快。**

## 日常使用

第一次设置完成后，以后正常使用不需要重复同步题库，也不需要每题重新框选。

程序启动后会读取上次保存的区域，并持续观察题干变化：

```text
检测到题目变化
        ↓
旧答案框消失
        ↓
检测到新题 · 识别中…
        ↓
OCR 识别
        ↓
本地题库 / JX3BOX 匹配
        ↓
在游戏中框出正确答案
```

如果临时不想让程序识别，可以点击 **暂停实时检测**。如果某一题没有自动触发，可以点击 **立即检测** 强制识别当前画面。

---

## 题库需要每次同步吗？

**不需要。** 题库同步一次后会保存在本地。

通常只有第一次使用、想获取远端新增题目、本地题库被手动删除，或者想主动刷新题库时，才需要再次点击 **同步题库**。

---

## 遇到题库没有的题怎么办？

程序支持 **边用边补**。

如果本地题库和 JX3BOX 都没有找到当前题目，主界面会自动显示题干和选项。你只需要点击正确答案，程序就会立即保存为用户题目、刷新本地索引，并在当前题上框出答案。

下次再遇到同一道题会直接自动识别。用户补录题目的优先级高于 JX3BOX，即使以后远端出现同一道题，也会优先使用你自己确认过的答案。

---

## 更新程序会不会丢题库？

不会。

Windows 版本的题库和设置保存在：

```text
%LOCALAPPDATA%\jx3-ocr-keju\
├─ questions.db
└─ settings.json
```

因此下载新版本覆盖旧程序、删除整个 `dist`、重新解压 Release 或重新构建程序，都不会删除本地题库和自己补录的题目。

---

## 隐私说明

OCR 图片在本机处理，程序不会把游戏截图上传到 JX3BOX。

查询顺序是：

```text
本地题库
   ↓
本地模糊匹配
   ↓
本地未命中
   ↓
仅发送 OCR 识别后的题目文字到 JX3BOX
```

远端查询需要时只会发送识别后的文字，不会发送截图。

## 状态说明

**实时检测中**：程序正在观察框选区域，等待题目变化。

**检测到新题 · 识别中…**：已经确认换题，正在执行 OCR 和题库匹配。

**已命中**：已经找到题库答案，并尝试在游戏画面上标出正确选项。

**题库未收录**：当前题目没有在本地或远端找到，可以直接在主界面选择正确答案进行补录。

**已检测新题 · 未定位答案**：题目已经匹配成功，但 OCR 没有准确找到对应选项在屏幕上的位置，通常重新框选完整的题目与选项区域即可改善。

## 常见问题

### 换题以后没有自动识别

先确认程序顶部显示 **实时检测中**。如果仍然没有触发，可以点击 **立即检测** 验证当前画面是否能正常 OCR，然后重新框选区域，并尽量只包含题目和答案选项。

### 识别速度比较慢

优先缩小框选区域，不要框整个游戏窗口。程序启动后会在后台预热 OCR，刚启动时等待几秒再进入科举界面，首次识别通常会更稳定。

### 找到答案了，但绿色框位置不正确

重新框选区域，并确保题目完整、所有选项完整、文字没有被其他 UI 遮挡。

### 每次启动都要重新框选吗？

不用。程序会保存上一次的识别区域。只有游戏分辨率、窗口位置、UI 缩放或科举界面位置发生明显变化时，才建议重新框选。

### 每次启动都要重新同步题库吗？

不用。同步过一次以后直接使用即可。

### 为什么本地题库数量比远端一次同步的数量多？

本地除了批量同步的题目，还可能包含远端查询时自动缓存的题目和你自己补录的题目，因此数量更高是正常现象。

## 数据备份

最重要的文件是：

```text
%LOCALAPPDATA%\jx3-ocr-keju\questions.db
```

如果想完整备份题库、用户补录和设置，直接备份整个 `%LOCALAPPDATA%\jx3-ocr-keju\` 目录即可。

## 给开发者

项目使用 Python 3.13、PySide6、RapidOCR、ONNX Runtime、OpenCV、SQLite、RapidFuzz、httpx、PyInstaller 和 uv。

```powershell
uv sync --extra dev
uv run ocr-keju-gui
uv run pytest
uv run rapidocr check
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

调试 CLI：

```powershell
uv run ocr-keju stats
uv run ocr-keju sync
uv run ocr-keju search "题目文字"
uv run ocr-keju ocr-image .\question.png
```

推送 `v*` 标签后，GitHub Actions 会自动构建 Windows x64 Release。
